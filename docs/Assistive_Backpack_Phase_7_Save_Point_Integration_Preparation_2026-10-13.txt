3. ARCHITECTURE AND DESIGN DECISIONS
===============================================================================

3.1 Hardware-independent core
The shared core should not depend on Arduino APIs or desktop console I/O.
Avoid iostream, Serial, LCD drivers, RC522 drivers, and other hardware APIs in
the shared core.

The core owns:
- Inventory data and inventory operations.
- Task registration and task management.
- Backpack state-machine coordination.
- Event generation and queueing.

Platform/application layers own:
- Desktop: std::cout and terminal interaction in DebugConsole.
- Arduino: Serial interaction in DebugConsoleArduino.
- RFID adapter: RC522 setup and tag detection.
- Feedback adapter: audio, LEDs, display, and related outputs.

3.2 Single authoritative core source
Shared core source is stored in:
firmware/libraries/AssistiveBackpackCore/src/

Desktop CMake compiles the shared implementation files from this location.
Arduino IDE uses the same directory as an Arduino library. This avoids
maintaining separate copies of the core implementation.

Desktop-only files include:
firmware/backpack-core/include/DebugConsole.h
firmware/backpack-core/src/main.cpp
firmware/backpack-core/src/DebugConsole.cpp

3.3 Inventory display refactor
Inventory previously contained:
    void printInventory() const;
and an implementation using std::cout and <iostream>. This prevented Arduino
AVR compilation.

Changes made:
- Removed printInventory() declaration from Inventory.h.
- Removed Inventory::printInventory() implementation from Inventory.cpp.
- Removed <iostream> from Inventory.cpp if no longer required.
- Added a public index accessor:

    Item* Inventory::getItemAt(uint8_t index)

  The function returns nullptr when index >= itemCount; otherwise it returns
  &items[index].

This permits display code to iterate via the public interface without exposing
the private array. `findItem(uint32_t tagID)` searches by tag ID; it must not be
used as an index lookup.

The desktop DebugConsole now formats the inventory output. The user added or
used these display helpers:
- itemName(item->type), for readable item-type names.
- locationName(item->location), mapping:
    Location::Unknown  -> "Unknown"
    Location::Outside  -> "Outside"
    Location::Backpack -> "Backpack"
  and returning "Invalid location" for an unexpected enum value.

These are presentation helpers and should remain in the console layer rather
than being reintroduced into Inventory.

3.4 Fixed-width integer compatibility
The Arduino compiler reported:
    fatal error: cstdint: No such file or directory

The affected headers were Backpack.h, Config.h, Inventory.h, Item.h, Task.h,
and TaskManager.h. Their <cstdint> includes were changed to <stdint.h> for
Arduino AVR compatibility. A separate leftover iostream include in a
debugging section was subsequently removed, after which the basic Arduino
sketch compiled.

Always re-run both the desktop build and Arduino compile after changing shared
headers.

6. CORE API AND BEHAVIOUR NOTES
===============================================================================

This section summarises known behaviour. Inspect the actual current source
before relying on exact signatures not explicitly listed.

Inventory:
- clearInventory(): clears inventory contents.
- getItemCount(): returns current item count.
- findItem(uint32_t tagID): searches by tag ID; returns Item* or nullptr.
- getItemAt(uint8_t index): newly added index accessor; returns Item* or nullptr
  if the index is out of range.
- registerItem(uint32_t tagID, ItemType type): registers tag/type mapping.
- addItem(uint32_t tagID): marks a registered item as being in the Backpack.
- removeItem(uint32_t tagID): marks a registered item as Outside.
- hasItem(ItemType type): checks whether the requested type is present.
- getItemType(uint32_t tagID): returns ItemType; use findItem() when needing to
  distinguish an unregistered tag from a registered unknown item.

Backpack / state machine:
- Backpack owns a private TaskManager.
- Backpack::registerTask(const Task& task) forwards registration to its private
  TaskManager; callers should not access TaskManager directly.
- Known states: IDLE, CHECKING_INVENTORY, ACQUIRING_ITEMS, TASK_REMINDER.
- begin() initialises the core.
- getState() exposes current state.
- startTask(...) starts a registered task and checks inventory.
- stopTask() stops the active task.
- itemAdded(...) and itemRemoved(...) report resolved item entry/removal.
- itemScanned(tagID) exists as an integration hook; inspect its exact current
  behaviour and signature before using it.
- One active task at a time.
- Inventory is the single source of truth for item location and task checks.
- Unknown tags may be registered as ItemType::Unknown and emit UnknownRFID;
  verify exact edge-case behaviour in source.

Events:
- EventGenerator and event structures are in the shared core.
- Previous notes specify MAX_EVENTS = 30.
- Event names discussed previously include TaskStarted, TaskStopped,
  TaskComplete, TaskReminder, ItemRequired, ItemAcquired, UnknownRFID,
  InventoryFull, and Item_not_required. Verify exact spellings and enum names in
  Events.h/EventGenerator.h before using them.
- During feedback integration, carefully define who consumes the event queue.
  One consumer should not remove an event before another output has responded.

Tasks:
- Tasks require ItemType values, not RFID tag IDs.
- Multiple tasks can share required items.
- Core remains the authority for active task and task-completion logic.
- Only one active task at a time.

Desktop DebugConsole:
- Source is firmware/backpack-core/src/DebugConsole.cpp.
- Uses desktop terminal I/O; do not include it in the Arduino library.
- Inventory output uses getItemCount() and getItemAt(index).
- User improved output to show readable item and location names.

7. ARDUINO DEBUG CONSOLE FILES — PREPARED, NOT VERIFIED
===============================================================================

Files generated in the preceding conversation:
    DebugConsoleArduino.h
    DebugConsoleArduino.cpp

They were provided as downloadable files. They should be placed alongside the
Arduino sketch (or in another Arduino application-layer folder), not inside
AssistiveBackpackCore/src, because they use Arduino Serial APIs.

Intended features:
- Serial.print()/Serial.println() rather than std::cout.
- Line-oriented Serial Monitor commands.
- Commands for help, simulated scan, add/remove, task start/stop, inventory,
  status, events, and RFID/type registration.
- Fixed-size character input buffer rather than dynamic String.
- Incremental input processing from update() to avoid waiting for a complete
  line through a blocking timeout.
- Readable item and location output.

These files are an initial draft and have NOT been compiled against the exact
current core. Before using them:
1. Check every method referenced against Backpack.h and its implementation.
2. Verify the exact signatures and return types for itemScanned, itemAdded,
   itemRemoved, startTask, stopTask, getState, isTaskActive, isTaskComplete,
   hasEvent, and getEvent.
3. Verify the event type and fields; the draft expects fields named type, item,
   and task, but this must be checked.
4. Verify ItemType and TaskType enum values in Item.h and Task.h.
5. Decide how the console accesses the exact Inventory instance owned/used by
   Backpack. Do not pass a separate, disconnected Inventory instance.
6. Check that displaying/draining events does not prevent future feedback
   consumers from receiving them.
7. Compile in Arduino IDE, correct interface mismatches, upload to Uno, and
   test commands one at a time.

The BasicBackpack smoke-test sketch previously declared Backpack locally inside
setup(). That is acceptable only for the initial compile-and-begin check,
because loop() did not use it. Before using the console or other subsystems,
make the Backpack object persistent for the whole sketch lifetime.
